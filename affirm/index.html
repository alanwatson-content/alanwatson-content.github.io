How I work

User-centred design (UCD), applied to the words.

  • Start from what people need to do

    What the organisation wants to say comes second. And the unhappy paths (a failed switch, a delayed engineer) get as much care as the sales pages.

  • Test the words

    I've never had a dedicated user researcher, so I plan and run my own testing: comprehension tests, 7-second tests and task success before anything goes live. An ease score on its own has fooled me before, so I check it against what people actually did.

  • Honest by default

    Say what happens, including the awkward bits. Exit fees, 2 engineer visits, a price that changes after 6 months. Key facts go in the main text rather than the small print.

  • Help everyone write well

    Style guides, accessibility guidelines, testing templates, training, and tools I build with AI when they'll save everyone time. The words need to hold up without me in every ticket.
