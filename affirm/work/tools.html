Tools that keep the words right

Good words don't help much if they sit in a backlog, or if the next person writing a text message can't find them. In 2025 and 2026 I built a few tools to fix that, mostly with AI. Each one started with a problem I kept running into.

Copy changes as their own tickets

Small copy fixes waited to be bundled into someone else's work. And tickets were written from Figma screenshots, which aren't always what's live.

giffgaff is piloting a way of building where AI agents pick up tickets and do the build. If a copy change is written as a ticket the agents can read, it doesn't have to wait for an engineer's time.

I mapped the process from content idea to ticket and agreed a ticket format with the team: the page, links to the current and new Figma frames, old copy, new copy, why it's changing, and one Given/When/Then scenario. Then I built a shareable page that does it. Paste the old and new copy, or point it at two Figma frames and it pulls the copy out. It shows you the ticket first, and you can tell Claude in a chat box if a string's wrong or something's missing. It can change the ticket but not the design. Then you fire it, and it raises the Jira ticket through your own Atlassian and Figma connections.

Copy changes now go through as their own tickets. Testing the page on real broadband tickets also turned up something nobody had spotted: the Figma files didn't match what was live. I had the 40-odd buy journey screens checked against the code, got Figma updated, and killed a ticket that would have changed live copy to match a wrong design. I've updated the skills behind this tool to check the old copy actually exists before it raises anything.

A brand voice skill for the team's AI assistant

The content team had started using an AI assistant for first drafts and checks. Without the style guide, it had nothing to write to.

People were going to use it anyway. Better that it starts from our voice and our rules than from nothing.

So I built a skill for Claude that holds the voice principles, the volume dial for each channel, the glossary, and the inclusive and accessible writing rules. I asked the content team which brand documents it should draw on.

A first draft of an SMS or a help article now starts from the same place whoever asks for it. When the new voice landed in September 2026, I rewrote the skill that week so the tooling didn't keep producing the old one.

It's better at checking than writing. On the tone of voice rewrite I binned its fluent first drafts and wrote the final version myself. Run over a Figma flow before handoff, it caught a competitor's name in an FAQ, leftover lorem ipsum and steps in the wrong order.

Finding where the words live

Before you can change copy you have to find it. giffgaff.com has no content management system, so a single phrase can be hardcoded in several places. A brand refresh needs every one of them.

Reading 31 code repositories by hand isn't a sensible job for a content designer, so I had AI agents sweep them and report where member-facing wording lives. Then I wrote a "find every mention first" process any product team can use before changing copy: search every repository, sort what you find into member-facing, internal or test, trace shared components to where they show up, and write a file-by-file ticket that says what's out of scope.

The words sit in about 63 files across 16 repositories, a lot of it hardcoded, in 4 different conventions. That went to the brand refresh team, fed into planning for the AI build pilot, and became the starting point for the CMS requirements I drafted for web and app.

Writing for the help bot

giffgaff's AI help agent answers questions before they reach an adviser, and it can only be as good as what it reads. I wrote or reviewed 7 broadband help articles so it had what it needed, split the muddled switching article into one for joining and one for leaving so it had a clean source for each, and asked it the questions myself after changes to check it gave the new answer. More on that in Help content anyone can use.

Where I stop

I still test the words with people before anything goes live. And when a tool touches something engineers, legal or security own, I bring them in.
